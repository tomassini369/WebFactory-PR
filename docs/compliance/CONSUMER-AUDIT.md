A consent receipt records policy identifier, server acceptedAt, adult attestation, terms and privacy flags. It contains no IP address, DOB, payment credentials or birth documentation. Registration stores it only on a new consumer record; existing/restricted profiles cannot be overwritten through signup. If receipt persistence fails, the profile gate still requires acceptance. New policy identifiers must correspond to reviewed documents; this preview identifier does not claim production publication.

Delete Marketplace profile is **not** delete shared login account. It deliberately does not erase business ownership, reservations, payment records or unrelated merchant customer records. Contact `info@webfactorypr.com` for shared-account deletion, records review, or underage eligibility review. This existing published contact is reused; delivery/operational staffing must be confirmed by the owner. Underage status has no self-service release. Authorized operations must review the authenticated request and canonical Identity subject before any restriction release; no admin release/listing UI or automatic identity deletion was added. Do not ask minors to upload documents. Never use the business-account deletion endpoint for this request because it can delete owned businesses/cancel subscriptions.

## Follow-up: operator eligibility review

The platform administrator now has `ConsumerEligibilityReview` in the administrative operations area and `/.netlify/functions/admin-consumer-review`. The list contains only opaque hashed profile references, request time, revision, restriction status and latest decision/time; no names, favorites, email or identity documents. An actual external support assessment remains required. It is not an age-verification service or a finding of legal contractual capacity.

Recording a decision requires platform-admin authorization, same origin, the current revision, ETag concurrency, an explicit completed-review attestation and a concise reason. Do not enter birth dates, documents, credentials or sensitive information in that reason. `keep_restricted` leaves the account blocked. `allow_reattest` permits only a fresh acceptance: it removes previous consent and does not restore erased name, municipality or favorites. It does not grant business membership or bypass normal authentication. A maximum25-entry internal review history records actor/time/decision/reason; the consumer-facing projection excludes this history. Consumer deletion and rereport retain this bounded security audit so they cannot conceal the reasoned review or bypass an existing restriction. No fixed retention period is invented; supervised archival/retention decisions remain an operator duty.

Five new isolated tests cover administrator-only access and list minimization, cleared-review reacceptance, restriction persistence across deletion, private history, CSRF, stale revision, missing ETag and concurrent write failure. Existing nine Marketplace tests also pass. No real consumer record was opened or changed.
